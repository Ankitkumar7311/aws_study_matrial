3. VPC
VPC = Virtual Private Cloud

A VPC is your private network inside AWS.

Think of it like your own network in the AWS cloud.

Example:

AWS Cloud
└── VPC
    ├── Subnet 1
    │   ├── EC2
    │   └── EC2
    │
    └── Subnet 2
        ├── EC2
        └── EC2

Example VPC CIDR:

10.0.0.0/16

This means the VPC has a large private IP address range.

4. Subnet

A subnet is a smaller network inside a VPC.

Example:

VPC
10.0.0.0/16

        |
        +---- Public Subnet
        |     10.0.1.0/24
        |
        +---- Private Subnet
              10.0.2.0/24

EC2 instances are launched inside subnets.

Public Subnet

Usually used for resources that need internet connectivity.

Example:

Internet
   ↓
Internet Gateway
   ↓
Public Subnet
   ↓
EC2
Private Subnet

Usually used for resources that should not be directly accessible from the internet.

Example:

EC2 Application
      ↓

7. Elastic IP

An Elastic IP is a static public IPv4 address.

Normally, an EC2 public IP can change after stopping and starting the instance.

Elastic IP gives you a persistent public IP.

27. What is Reverse Proxy?

This is the most important topic.

A reverse proxy receives the client's request and forwards it to another server/application.

Without reverse proxy:

Browser
   |
   ↓
:8000
   |
   ↓
Python Server

With reverse proxy:

Browser
   |
   ↓
:80
   |
   ↓
Nginx
   |
   ↓
:8000
   |
   ↓
Python Server

The user only sees:

http://YOUR_PUBLIC_IP

They don't need to specify:

:8000
28. Why Use Reverse Proxy?

Suppose your application runs on:

127.0.0.1:8000

You don't necessarily want users directly accessing that application port.

Instead:

Internet
   ↓
Nginx :80
   ↓
Application :8000

Benefits include:

Hide backend port
Centralize HTTP handling
SSL/TLS termination
Routing
Load balancing
Security
Multiple applications on one server

32. Configure Nginx Reverse Proxy

Open:

sudo vim /etc/nginx/sites-available/default

Use this configuration:

server {
        listen 80 default_server;
        listen [::]:80 default_server;

        root /var/www/html;

        index index.html index.htm index.nginx-debian.html;

        server_name _;

        location / {
                proxy_pass http://127.0.0.1:8000;

                proxy_set_header Host $host;
                proxy_set_header X-Real-IP $remote_addr;
                proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
                proxy_set_header X-Forwarded-Proto $scheme;
        }
}
33. Understanding proxy_pass

This is the key line:

proxy_pass http://127.0.0.1:8000;

It means:

Forward the request received by Nginx to port 8000 on the same machine.

Flow:

Client
  |
  | HTTP :80
  ↓
Nginx
  |
  | proxy_pass
  ↓
127.0.0.1:8000
  |
  ↓
Python Server
34. Understanding Proxy Headers
Host
proxy_set_header Host $host;

Passes the original host name to the backend.

Real IP
proxy_set_header X-Real-IP $remote_addr;

Passes the client's IP address.

Forwarded For
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

Maintains the proxy chain/client IP information.

Protocol
proxy_set_header X-Forwarded-Proto $scheme;

Tells the backend whether the original request used:

http

or:

https

41. Important Difference: Forward Proxy vs Reverse Proxy
Forward Proxy

Proxy works on behalf of the client.

Client
  ↓
Forward Proxy
  ↓
Internet
Reverse Proxy

Proxy works on behalf of the server/application.

Client
  ↓
Reverse Proxy
  ↓
Backend Server

Nginx in our example is a:

Reverse Proxy

43. Troubleshooting
Problem 1: Nginx doesn't start

Run:

sudo nginx -t

If there is a syntax error, fix the configuration.

Then:

sudo systemctl restart nginx
Problem 2: Browser shows "Connection timed out"

Check AWS Security Group.

Make sure:

HTTP
TCP
80
0.0.0.0/0

is allowed.

Problem 3: Nginx works but backend doesn't

Check:

curl http://localhost:8000

If this fails, your Python server isn't running correctly.

Start:

python3 -m http.server 8000
Problem 4: Port 8000 is already in use

Check:

sudo ss -tulpn | grep 8000
Problem 5: Nginx gives 502 Bad Gateway

Usually this means:

Nginx
  ↓
127.0.0.1:8000
  X
Backend unavailable

Check:

curl http://127.0.0.1:8000

and make sure your backend is running.
